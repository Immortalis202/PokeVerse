# Complete item and ability roadmap

Audited 22 October 2026 against the current worktree, `rules/ability-coverage.json`, `src-tauri/src/combat/items.rs`, and all supplied `Pokerole-Data/v3.0/Abilities` and `Items` cards. This document supersedes stale dependency wording in the older backlog; it does not change runtime registry statuses.

**Delivery state:** application 0.30.0 / engine 0.23.0-core / protocol 31 delivers milestone 6. All earlier batches remain enabled; saved encounters retain historical rules. See [item and medicine rules](battle-item-completion.md).

**Coverage:** all 305 abilities are accounted for: 242 automated, 60 partial and 3 manual. All 236 items remain in the companion CSV. The table retains its original 105-entry audit scope, including delivered entries. As One precedence and Teraform Zero unique stalemates retain explicit partial boundaries. Automated covers the stated scope.

Scope: in-battle abilities and transformations are core. Out-of-battle ability effects are excluded. Trainer-target damage, lethal wounds, automatic Will recovery, Dynamax/Gigantamax, Max Moves and Z-Moves remain excluded. An item's presence here does not authorize unrelated outside-battle automation. Capture automation remains separately deferred. Ordinary inventory possession and equipment transport do not imply executable item effects.

## Coverage and maintenance

- `ability-roadmap.csv`: one row for each of the 305 source abilities, with registry status, current assessment, batch, dependencies, scope and printed effect.
- `item-roadmap.csv`: one row for each of the 236 source items, with catalog identity, category/pocket, battle status, work and printed description.
- Completion must update the assessment and runtime registry together. Preserve explicit manual choices where the supplied rules require GM discretion; do not equate those with missing host validation.
- This inventory covers the supplied catalog, not hypothetical items missing from it. Booster Energy, typed memory discs and Ogerpon masks are not present as supplied item definitions; their existence in other games is not authority to invent Pokerole effects. RKS System and Embody Aspect therefore need reviewed identity/input metadata in the transformation batch.
- Main code: `src-tauri/src/combat/items.rs` (staged items), `combat/abilities.rs` and sibling modules (battle abilities), `combat/sequencing.rs` (sequencing), `src/HeldItemControls.tsx` (item decisions), `src-tauri/src/privacy.rs` (projections). Runtime registry: `rules/ability-coverage.json`.
